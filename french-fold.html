Metadata, Standards & Ontologies

P. 2 / 8
DEFINITIONS & 3 CLASSES OF METADATA
Metadata Definition: Structured data about data that describes, identifies, explains, locates, and facilitates the retrieval and management of an information resource.
• Descriptive: Identifies content for discovery (Title, Author, Subject keywords, Abstract).
• Structural: Describes internal sequencing & compound object assembly (Chapter hierarchy in an e-book, page order of scanned manuscript).
• Administrative: Manages the resource over time. Sub-types:
  1. Technical: File format, file size, compression, camera specs.
  2. Rights: Copyright ownership, licensing, usage permissions.
  3. Preservation: Archival integrity, SHA-256 checksums, migration history.
RDA VS AACR (CATALOGUING REVOLUTION)
AACR (Anglo-American Cataloguing Rules): Legacy rules designed for physical 3x5-inch library card catalogues.
RDA (Resource Description and Access): Modern web-native content standard built on the FRBR (Functional Requirements for Bibliographic Records) entity-relationship model (Work, Expression, Manifestation, Item). Designed for digital networked resources.
XML, OWL & DUBLIN CORE (DCMI)
• XML (eXtensible Markup Language): Structural text markup using hierarchical user-defined tags (<book><title>...</title></book>). Machine/human readable.
• OWL (Web Ontology Language): Semantic Web language built on RDF/XML to formally define domain ontologies, classes, properties, and relationships for machine reasoning.
• Dublin Core (15 Core Elements): Title, Creator, Subject, Description, Publisher, Contributor, Date, Type, Format, Identifier, Source, Language, Relation, Coverage, Rights. Simple DC (15 strings) vs Qualified DC (adds qualifiers & vocabularies).

Databases & Architectural Modeling

P. 3 / 8
DATABASE VS DBMS & RELATIONAL KEYS
• Database: An organized collection of logically related structured data.
• DBMS: The software suite (e.g. MySQL, PostgreSQL, Oracle) used to create, query, administer, and secure the database.
• Primary Key (PK): Unique attribute identifying every record (e.g. StudentID).
• Foreign Key (FK): An attribute matching the Primary Key in another table to enforce Referential Integrity without data duplication.
ACID TRANSACTION PROPERTIES (EXACT EXAMPLES)
• Atomicity: "All or nothing" — if any sub-operation fails, the entire transaction rolls back (e.g. bank transfer: funds deducted from Account A must reach Account B; if power fails halfway, funds revert).
• Consistency: Database must transition from one valid state to another, obeying all integrity constraints and schema rules.
• Isolation: Concurrent transactions execute independently without data corruption.
• Durability: Once committed, transaction results are permanently saved in non-volatile storage, surviving system crashes.
RDBMS VS NOSQL COMPARISON MATRIX
Feature Relational (RDBMS) NoSQL
Data Model Structured 2D tables (rows/cols) Flexible JSON docs, key-value, graph
Schema Rigid, fixed predefined schema Dynamic, flexible, schema-less
Scaling Vertical (bigger server) Horizontal (sharding across clusters)
Consistency ACID (Strict consistency) BASE (Eventual consistency)
Use Cases Banking, Student marks, ERP Facebook feeds, Clickstreams, Big Data

Data Validation & Quality Checks

P. 4 / 8
VALIDATION VS VERIFICATION (TRAP #1)
• Data Validation: Automated computer algorithms that check data follows strict system rules before database acceptance.
• Data Verification: Checking that copied/entered data accurately matches the original source (e.g. double entry, proofreading, email verification links).
THE 4 PRIMARY VALIDATION CHECKS (MUST MEMORIZE!)
1. Type Check:
Ensures entered data conforms to the expected data type.
Exam Example: An Age field accepts integer 21 but immediately rejects text string "twenty-one".

2. Range Check:
Verifies a number or date falls between legal minimum and maximum boundaries.
Exam Example: Exam mark percentage must be between 0.0 and 100.0; rejects 105 or -5.

3. Presence Check:
Ensures mandatory fields cannot be left blank or submitted as NULL.
Exam Example: The StudentID and Surname fields must be filled before the form can be submitted.

4. Format Check:
Validates that input adheres strictly to a predefined pattern or regular expression.
Exam Example: UP student email must end with @tuks.co.za; SA National ID must contain exactly 13 numeric digits.
ADDITIONAL INTEGRITY CHECKS
• Length Check: Characters within limits (e.g. password ≥ 8 chars).
• Check Digit: Mathematical calculation on final digit (e.g. ISBN, credit cards).
• Lookup Check: Value exists in reference table (e.g. valid SA province codes).

Search Engine Technology & Indexing

P. 5 / 8
THE 3-STAGE SEARCH ENGINE LIFECYCLE
1. Crawling: Automated bots / web crawlers (e.g. Googlebot, spiders) discover new and updated pages by systematically traversing hyperlinks across the web. Governed by robots.txt and XML sitemaps.

2. Indexing: Downloaded HTML pages are parsed, stripped of boilerplate, tokenized, and normalized (stop-word removal, stemming). Content is stored in an Inverted Index.

3. Ranking & Retrieval: When a user enters a query, the search engine parses keywords against the inverted index, scores matching pages using algorithms (PageRank, relevance, backlinks, speed, mobile usability), and returns the ranked SERP.
THE INVERTED INDEX (CORE EXAM CONCEPT)
Definition: The foundational database architecture used by search engines that maps individual words/terms directly to the list of document IDs containing them.
Why it matters: Sequential full-text scanning across billions of web pages is computationally impossible. An inverted index enables instant O(1) / logarithmic query retrieval.
"database" → [Doc 1: pos 4], [Doc 3: pos 12], [Doc 7: pos 2]
"metadata" → [Doc 1: pos 8], [Doc 2: pos 1], [Doc 4: pos 5]

• Backlinks (Off-Page): Hyperlinks from external authoritative sites acting as digital "votes of confidence" (Domain Authority / PageRank).

Model Essay: Implement Website SEO

P. 7 / 8
PARAGRAPH 1: DEFINITION & INBOUND MARKETING (3 MARKS)

Search Engine Optimisation (SEO) is the strategic methodology of techniques used to increase the quality and volume of organic (unpaid) traffic to a website by achieving high rankings on search engine results pages (SERPs). Its core purpose is facilitating inbound marketing—allowing prospective users actively searching for relevant information to discover the platform organically.

PARAGRAPH 2: ON-PAGE OPTIMIZATION (3 MARKS)

On-page implementation directly optimizes content and HTML markup. High-intent keywords are identified and integrated naturally into original content. Each page features a unique <title> tag under 60 characters and a compelling meta description under 160 characters. A strict heading structure with a single <h1> and nested <h2>/<h3> elements is enforced, alongside descriptive alt text on all images and clean, human-readable URL slugs.

PARAGRAPH 3: TECHNICAL & OFF-PAGE SEO (3 MARKS)

Technical SEO guarantees search bots can efficiently crawl and index the site. This requires rapid page speeds (image compression, caching), responsive mobile-first design, HTTPS encryption, and clean XML sitemaps submitted with a configured robots.txt. Off-page SEO complements this by acquiring authoritative backlinks from reputable third-party domains, building domain authority.

PARAGRAPH 4: WHITE-HAT VS BLACK-HAT ETHICS (3 MARKS)

Implementation must strictly follow White-Hat ethics, prioritizing human user experience and compliance with search engine guidelines. Manipulative Black-Hat practices—such as keyword stuffing, hidden white text on white backgrounds, or purchasing links—must be avoided, as algorithms automatically penalize or completely de-index violating websites.
